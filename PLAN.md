# PLAN — voxloop

## The real problem

Voice assistants that can't be interrupted aren't conversational — they're
radio. The hard part isn't STT or TTS quality; it's the turn engine: when
does the user's speech start, when does a turn end, what gets cut the
instant they barge back in, and how tools run without freezing the mouth.
Frameworks that solve this (LiveKit, Pipecat) arrive as dependency trees
that own your event loop and your process. On a small box, or an
air-gapped one, that's the wrong trade.

**voxloop's answer:** the turn engine is ~150 lines of state machine over
an energy VAD, in pure stdlib Python. It runs offline on synthetic PCM,
and STT/TTS plug in later as CLI adapters — the engine's semantics
(interruption, turn-taking, tool concurrency) are testable without any
model at all.

## Goals — what this can become at its highest

The ceiling is a **dependency-free voice-loop core** that any agent can
embed:

- Sub-second barge-in by construction: interruption is decided per
  20 ms frame and cuts playback *before* any transcription happens.
- Model-agnostic turn semantics: the same engine tests pass whether the
  brain is a stub, a local llama.cpp loop, or a remote LLM — because the
  tests only exercise the engine, not the brain.
- Tools-while-talking as an architectural guarantee: `brain()` runs
  synchronously in the turn path, `speak()` is non-blocking, so no tool
  latency ever silences the mouth mid-phrase.
- A regression rig with fixtures: scripted conversations as WAV files,
  VAD behavior pinned by deterministic synthetic audio (sine speech,
  zero silence, sub-threshold hum).

## Non-goals (deliberate)

- No audio device layer (no ALSA/PortAudio). Frames come from anywhere.
- No VAD ML model. Energy VAD is the documented ceiling: clean rooms
  fine, noisy rooms need Silero — out of scope until it's a real problem.
- No streaming LLM integration. `brain()` is one callable; wire what you
  want.

## Checkpoint 1 — Engine + offline proof (DONE in this commit)

`vad.py`: pure-Python RMS (audioop-free, 3.13-safe), energy VAD with
attack/hangover, frame events. `engine.py`: `TurnEngine` state machine
(idle/listening/thinking/speaking) with barge-in that cuts playback at
the first qualifying frame, and tool execution inside the turn path while
the speaker stays non-blocking. `scripts/make_fixtures.py`: deterministic
WAVs. `tests/test_all.py`: 12 tests — RMS math, VAD trigger/refusal,
hangover bridging, two-turn conversation parsing, barge-in latency
(logic-level: interrupt fires at the 40 ms attack frame), barge-in
disable switch, tools-while-talking ordering.

## Checkpoint 2 — Real audio I/O adapters (NEXT)

- `adapters/whisper_subprocess.py`: pipe the utterance window to a
  `whisper-cli` process (local CLI tool, not a Python dependency).
- `adapters/piper_subprocess.py`: stream reply text to `piper` for
  synthesis; playback via `ffplay`/device sink.
- `mic_file.py` + `mic_ws.py`: feed the engine from a WAV/pipe or a raw
  WebSocket (reusing the stdlib ws pattern from the tryrest repo).
- Latency instrumentation: per-stage timestamps in the log; a test
  asserting end-to-end turn latency on synthetic audio.

## Checkpoint 3 — Conversational memory + multi-party turns

- Rolling conversation window passed to the brain.
- Backchannel handling (short "mm"/"yeah" bursts don't take turns:
  minimum-speech-duration gate).
- A scripted multi-party fixture (two voices, different tones) with
  expected turn assignments.

## Rollback / recovery

Greenfield library: rollback is `git revert`. No devices are opened, no
processes spawned (Checkpoint 1), no state outside the test process. The
fixture WAVs are regenerated by script, never hand-edited.

## Offline guarantee

Stdlib only (`array`, `math`, `wave`, `time`, `unittest`). Tests generate
and consume their own audio; nothing downloads, nothing calls out. The
adapters in later checkpoints invoke local CLI binaries (whisper.cpp,
piper) — still no network, still no Python dependencies.
